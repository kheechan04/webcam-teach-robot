# 1단계: 웹캠 조종 (teleop)

코드: `scripts/teleop.py`, `src/webcam_teach_robot/ik.py`, `src/webcam_teach_robot/hand_tracking.py`

## 구조

```
웹캠 프레임 → MediaPipe 손 → 손바닥 중심 (u, v) + 깊이 z (핀홀)
          → 카메라 좌표 3D → 지수평활 → 클러치 기준점과의 차이 × 배율 → 로봇 목표 위치 (작업 상자 안으로 제한)
          → 우선순위 IK (1순위 위치, 2순위 집게 아래) → 위치 제어 모터 → MuJoCo 물리
엄지 끝~검지 끝 거리 / 손바닥 너비 (월드 좌표) → 집게 열림 정도
```

## 첫 조종 시도 (2026-10-01, `measurements/teleop/20261001_023656.csv`)

사용자 소감: 앞뒤는 맞음, **좌우가 반대**, **위아래가 잘 안 됨**, 집게는 잘 됨.

기록에서 확인한 것 (106초, 조종 중 1535프레임):

| 항목 | 값 |
|---|---|
| 손 인식률 | 98.6% |
| 루프 주기 | 중앙값 29.9 ms (약 30 fps), 95% 44.7 ms |
| 손 추적 / IK | 중앙값 13.4 ms / 2.7 ms |
| 목표가 x 상한(35 cm)에 막힌 프레임 | 36% |
| IK 위치 오차 >10 mm 프레임 | 46% |
| 너비 기준 깊이가 100 cm 넘는 프레임 | 2.4% (손을 옆으로 돌릴 때로 추정) |
| 프레임 간 손 이동 표준편차 (x, y, z) | 0.9, 0.22, **2.11** cm |

원인과 수정:

1. **좌우 반대** — 로봇 창 시점을 azimuth 180(로봇 앞에서 보는 거울 시점)으로 잘못 둠. 조종 방향 자체는 맞았다. → azimuth 0(로봇 뒤에서 보는 시점).
2. **위아래 안 됨** — 작업 상자(x 최대 35 cm)가 팔이 닿는 범위보다 넓어서, 목표가 너무 멀리 가면 팔이 쭉 펴진 채로 위아래를 못 움직였다. → IK로 도달 영역을 훑어서 상자를 x 14~30, y ±15, z 1~15 cm로 줄임.
3. **깊이 튐** — 너비 기준 깊이는 손을 옆으로 돌리면 크게 튄다. 기울이거나 돌리면 사진 속 길이는 짧아져 "멀다" 쪽으로만 틀리므로 길이·너비 중 작은 값을 쓰도록 바꿈("min"). 같은 기록에서 100 cm 넘는 프레임 2.4% → 0%.
4. 깊이 방향은 범위가 넓고 흔들려서 앞뒤 배율을 0.5로 따로 둠(좌우·위아래 0.7).

**연구 관점 메모:** 깊이가 틀리면 앞뒤만 틀리는 게 아니다. 손의 좌우·위아래 위치도 `(u − cx) × z / f`로 계산하므로 깊이 오차가 옆 방향 오차로 번진다. 조건 ④(가짜 깊이 오차)를 만들 때 이 전파도 같이 넣어야 한다.

## 두 번째 조종 시도 (2026-10-01, `measurements/teleop/20261001_024800.csv`)

사용자 소감: 훨씬 나음. **집게가 자연스럽지 않음**, 손목이 안 움직임, 가끔 **로봇이 의도보다 몸 쪽으로 붙음**.

| 발견 | 근거 | 조치 |
|---|---|---|
| 집게가 완전히 안 닫힘 | 엄지-검지 비율이 붙였을 때 0.4~0.9(닫힘 기준 0.35보다 큼). 완전히 닫힌 시간 1% | 비례 방식 → 히스테리시스 스위치(0.8 아래 닫힘, 1.0 위 열림). 같은 기록 재생 시 13번 전환, 닫힌 시간 21% |
| 몸 쪽으로 붙음 ① | 클러치 7구간 중 시작 순간 깊이가 12.7 cm, 21.8 cm로 튄 구간에서 로봇이 가까움 한계에 25%, 58% 머묾 | 한 프레임 깊이 변화 >10 cm 무시(게이트), 클러치 기준점 = 직전 10프레임 중앙값. 재생 시 3.8% 프레임 무시, 프레임 간 변화 95%가 3.5 → 1.8 cm |
| 몸 쪽으로 붙음 ② | 깊이 중앙값: 편 손 46.3 cm, 집은 손 55.3 cm (손을 실제로 뺐을 가능성도 있어 확실하지 않음) | **일부러 안 고침** → 조건 ③ 깊이 보정의 대상 |
| 손목 | wrist_roll은 0 고정(미연결), wrist_flex는 IK가 집게를 아래로 두려고 자동 조절(60~96°) | **결정 (a): roll 고정 유지.** 과제를 물체가 항상 같은 방향으로 놓이게 짜서 깊이 외 오차 원인을 줄인다 |

**설계 원칙 (기본 처리 vs 보정):** 모든 웹캠 조건에 공통인 "상식적인 기본 처리"(게이트, 평활, 클러치 기준 중앙값, 길이·너비 중 작은 값, 집게 스위치)는 `src/webcam_teach_robot/teleop_mapping.py`에 둔다. 자세(기울기·집는 손모양)에 따른 깊이 치우침 보정은 조건 ③에서만 한다. 기본 처리에서 미리 고치면 ②와 ③의 차이가 사라진다.

## 세 번째 조종 시도 (2026-10-01, `measurements/teleop/20261001_025553.csv`)

사용자 소감: 집게 괜찮음, 몸 쪽으로 붙는 것 줄었음.

- 게이트로 무시한 프레임 0.1%, 집게 전환 20회, 닫힌 시간 25%, 루프 중앙값 30.0 ms.
- 클러치 3구간 모두 시작 기준 깊이 45~52 cm로 정상 → 원인 ①(기준점 튐)은 해결.
- 그런데 몸 쪽 한계(x=14 cm)에 붙은 시간은 45%(두 번째 36%). 한계에 있을 때 손 깊이 중앙값 58.3 cm, 아닐 때 47.4 cm → 손이 시작보다 약 10 cm 뒤. 집게 닫힘과는 상관 없음(한계 20%, 아님 28%).
- **열린 질문:** 실제로 손을 당긴 것인지, 깊이가 멀게 추정된 것인지 기록만으로는 못 가른다(참값 없음). 정식 측정에서 확인.
- 설계 수정: 처음 자세가 x=19 cm라 몸 쪽 여유가 5 cm뿐이었음 → 작업 상자 가운데 x=22 cm, z=6 cm로.

## 재생으로 발견한 자세 문제 (2026-10-01)

`scripts/render_replay.py`로 세 번째 기록의 관절 각도만 다시 그려 보니(웹캠 영상 없이), 조종 창에선 안 보이던 이상한 자세가 있었다. 재생의 집게 끝 위치는 기록값과 일치 → 실제로 그 자세였다.

- 목표가 몸 가까이·높은 곳(x 14~16, z 10~12 cm)일 때 어깨가 한계(−1.74 rad ≈ −100°)까지 젖혀지고 집게가 43° 기울었다.
- 한 장면은 어깨 모터가 명령(−1.56)을 못 따라가(−1.15) 목표보다 4 cm 낮았다.
- 원인: 작업 상자(2차)를 y=0 단면만 보고 정해서, 집게를 아래로 못 향하는 영역이 섞여 있었다.
- 조치: 3D 격자(7×7×5)로 확인해 x 16~28, y ±15, z 1~8 cm로 줄임 → 245점 중 99%가 위치 <2 mm·방향 <10° (최대 1.0 mm, 10.9°).
