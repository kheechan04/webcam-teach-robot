# M7 조건 ③ 깊이 보정 (2026-10-03)

- 코드: `src/webcam_teach_robot/depth_correction.py` (특징·보정), `scripts/fit_depth_correction.py` (맞추기·평가)
- 계수: `src/webcam_teach_robot/depth_correction.json` / 평가: `experiments/depth_correction_eval.json`, `docs/figures/depth_correction_eval.png`
- 조종에서 켜기: `uv run python scripts/teleop.py --depth-correction` (기록 JSON에 `"condition": 3`과 계수가 같이 저장됨)

## 방법

RootNet(ICCV 2019)식 구조(`docs/07-related-work-v2.md`): **핀홀로 구한 거리 × 손 자세로 예측한 보정 계수.**

    d_보정 = d_핀홀 × exp(w · 특징 + b)

- d_핀홀: 지금 조종 방식(손바닥 길이·너비 중 작은 값, 화각 60° 가정).
- 특징 6개. 조종 중에 매 프레임 MediaPipe 값만으로 구한다.
  - 핀홀 거리(로그)
  - 엄지-검지 비율
  - 손바닥 앞뒤 기울기: 사진 속 길이/너비 비를 3D 비로 나눈 값의 로그
  - 손바닥 법선의 카메라 방향 성분
  - 화면 가로·세로 위치
- 맞추기: 프레임마다 log(참값 / d_핀홀)를 능형 회귀(ridge)로 예측. **M5 1회차 35단계로만 맞췄다.**
  - 정규화 세기는 1회차 안에서 "자세×높이 조건 하나씩 빼고 맞추기"로 골랐다(α=100; 0.01\~100 사이는 거의 같음).
  - 특징 조합도 평가 전에 정했다(6개 전부). 아래의 특징 빼 보기는 평가 뒤에 원인을 보려고 한 분석이고, 모델 고르기에는 쓰지 않았다.
- 범위 자르기: 보정 계수는 1회차에서 본 범위(×0.72\~×1.13) 밖으로 나가지 않게 했다. 측정하지 않은 자세에서 엉뚱하게 크게 고치지 않으려는 것.
- **2회차 35단계로 평가.** 2회차는 맞추는 데도, 고르는 데도 쓰지 않았다.

## 지표: 조종에서 무엇이 중요한가

조종은 절대 위치가 아니라 **이동량**으로 움직인다(클러치·집기 잠금이 풀릴 때 기준점을 다시 잡는다). 그래서 일정한 평균 오차는 상관없고, 다음이 중요하다.
- **손 모양 튐:** 같은 거리·높이에서 손 모양(편/집은 × 정면/기울임)만 바꿨을 때 추정 거리가 달라지는 폭. 조종 중 손을 기울이면 로봇이 이만큼(× 앞뒤 배율 0.5) 앞뒤로 움직인다.
- **앞뒤 배율:** 실제로 손을 10 cm 밀었을 때 추정이 몇 cm 움직이나(1이 정답).
- **조건 간 범위:** 자세×높이 8조건의 평균 오차 중 가장 큰 값 − 가장 작은 값.
- 흔들림(단계 안 표준편차)과 평균 절대 오차도 같이 본다.

## 결과 (2회차, cm)

| | 평균 절대 오차 | 조건 간 범위 | **손 모양 튐** | **앞뒤 배율** | 흔들림 | 가로 위치 (왼/가운데/오른) |
|---|---|---|---|---|---|---|
| 지금 방식 (조건 ②) | 4.5 | 10.3 | 9.9 | 1.18 | 0.55 | +0.7 / −0.1 / −3.9 |
| 배율만 다시 맞춤 (비교) | 4.3 | 9.4 | 9.0 | 1.08 | 0.51 | −3.6 / −4.3 / −7.8 |
| **자세 보정 (조건 ③)** | **3.4** | **4.2** | **5.6** | **0.90** | 0.55 | −1.8 / −0.7 / −0.4 |

| 자세 · 높이 | 지금 | 보정 |
|---|---|---|
| 편 손·정면 · 웹캠 높이 / 낮게 | +0.9 / +0.0 | +0.2 / −1.0 |
| 편 손·기울임 · 웹캠 높이 / 낮게 | +1.7 / −0.8 | −1.3 / −4.0 |
| 집은 손·정면 · 웹캠 높이 / 낮게 | +3.5 / +1.0 | −0.3 / −2.6 |
| 집은 손·기울임 · 웹캠 높이 / 낮게 | +7.4 / +9.4 | −2.6 / −4.0 |

- 처음 보는 2회차에서 **손 모양을 바꿀 때 생기는 튐이 9.9 → 5.6 cm(약 43% 감소)**, 조건 간 범위가 10.3 → 4.2 cm로 줄었다. 흔들림은 늘지 않았다.
- 배율만 다시 맞추는 건(= 초점거리 보정) 거의 도움이 안 됐다. 오차가 "전체가 멀다"가 아니라 "자세마다 다르다"라서다.
- **너무 고친다:** 2회차에서는 모든 조건이 음수(가깝다 쪽)로 넘어갔다. 1회차의 집은 손·기울임은 +12.9/+15.1 cm였는데 2회차는 +7.4/+9.4 cm로 덜 틀렸기 때문이다. 기울기 특징은 두 회차가 거의 같았다(앞뒤 기울기 −0.15 vs −0.20, 법선 0.73 vs 0.72). 즉 **같은 자세로 보이는데 오차가 5\~6 cm 다른 부분**이 있고, 이 특징들로는 설명되지 않는다(기울기 45°는 눈대중이었다, `docs/06-depth-formal.md` 한계).
- 앞뒤 배율이 1.18(과장)에서 0.90(축소)으로 넘어갔다. 1에서 벗어난 정도는 0.18 → 0.10으로 줄었다.
- 가로 위치(오른쪽 끝 −3.9 → −0.4)는 가로 위치 단계가 1회차에 3개뿐이라 참고만 한다.

### 특징 빼 보기 (평가 뒤 원인 분석)

| 특징 | 절대 오차 | 조건 간 범위 | 손 모양 튐 | 앞뒤 배율 |
|---|---|---|---|---|
| 6개 전부 (채택) | 3.4 | 4.2 | 5.6 | 0.90 |
| 엄지-검지 비율 빼기 | 3.3 | 5.4 | 5.4 | 0.90 |
| 기울기 2개 빼기 | 3.3 | 6.8 | 6.5 | 0.89 |
| 거리 + 기울기 2개 | 3.3 | 5.3 | 5.3 | 0.89 |
| 거리만 | 3.5 | 7.3 | 6.9 | 0.83 |

- 기울기 특징이 가장 큰 몫을 한다. 엄지-검지 비율은 기울기와 겹치는 정보가 많다(집은 손일 때 손바닥 법선도 함께 바뀜).
- "거리만"으로도 꽤 좋아 보이는 건, 기울이면 멀게 읽히므로 "멀게 읽힌 것 = 기울였을 가능성"을 거리가 대신 알려 주기 때문이다. 대신 앞뒤 배율이 0.83으로 더 눌린다.

## 실제 조종 기록에 적용 (오프라인)

`measurements/teleop/`의 조종 기록 두 개에 남겨 둔 손 마디 원래 값으로 보정을 다시 계산해 봤다. 로봇을 다시 움직인 건 아니다.

| 기록 | 프레임 | 보정 계수 중앙값 (편 손 / 집은 손) | 프레임 간 깊이 변화 95% |
|---|---|---|---|
| 135635 | 4,494 | ×0.92 / ×0.79 | 3.32 → 2.65 cm |
| 141612 | 2,079 | ×1.01 / ×0.86 | 1.08 → 1.14 cm |

- 집은 손을 편 손보다 10\~13% 더 가깝게 고친다. 50 cm 거리면 약 5\~6 cm로, M5에서 잰 치우침과 같은 방향이다.
- 손가락을 붙이거나 벌리는 **순간**의 출렁임은 줄이지 못했다. 반쯤 붙인 손은 M5에서 재지 않은 자세다. 이 구간은 원래 집기 잠금(모든 웹캠 조건 공통)이 팔을 고정하는 시간이다.
- 웹캠 대신 이 기록의 손 마디를 넣어 `teleop.py --depth-correction --log`를 끝까지 돌려 봤다(기록 파일에 보정 거리·조건 번호·계수가 저장되는 것까지 확인, 시험 파일은 지움).

## 정리

- 조건 ③ 보정은 처음 보는 측정에서 **손 모양 튐을 약 43%, 자세 간 치우침 범위를 약 60% 줄인다.** 다만 다 없애진 못하고(튐 5.6 cm 남음), 너무 고치는 경향이 있다.
- 남는 오차의 일부는 "같은 자세로 보이는데 다르게 틀리는" 부분이라, 이 특징들로는 더 줄이기 어렵다. 그래서 조건 ②와 ③의 학습 결과 차이는 "깊이 치우침을 **이만큼** 줄였을 때 회복되는 몫"으로 읽어야 한다.
- 한계: M5와 같다(한 사람, 한 웹캠, 한 번의 측정 세션, 가만히 있는 손). 2회차는 1회차와 같은 날 이어서 측정했으므로, 다른 날·다른 조명에서의 성능은 모른다.
