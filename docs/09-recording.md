# M8 웹캠 시범 녹화 규칙 (2026-10-03 확정)

- 스크립트: `scripts/record_demos.py` → `measurements/demos_m8/`
- 조종 코드는 `src/webcam_teach_robot/teleop_rig.py` 하나를 자유 조종(`teleop.py`)과 녹화가 같이 쓴다. 조건 ②와 ③의 차이는 깊이 보정(`depth_correction.py`)을 켜느냐뿐이다. 옮기기 전과 같은 손 입력으로 목표 위치·집게가 프레임마다 똑같이 나오는 것을 확인했다.

## 규칙

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 개수 | 학습 배치 50개(`layouts_v1.json` train) × 조건 ②·③ = 100번 | 조건 ①과 같은 배치·같은 개수 |
| 순서 | 5개씩 10블록. 블록마다 같은 5개를 한 조건으로 다 하고 다른 조건으로 다시. 먼저 할 조건은 블록마다 ABBA 반복(A는 시드로 정함), 블록 안 배치 순서는 조건마다 섞음 | 연습 효과·피로가 한 조건에 쏠리지 않게 |
| 가리기 | 화면에 조건을 표시하지 않음(깊이 숫자도 숨김). 기록 JSON에만 남음 | 조작자가 조건을 알고 다르게 행동하는 것을 줄이려고 |
| 시간 제한 | 조종을 처음 건 때부터 90초 | 끝없이 붙잡고 있지 않게. 성공 기록 하나가 74초였음 |
| 다시 하기 | 같은 배치·조건 3번까지. 3번 다 실패하면 실패로 남기고 넘어감 | 실패도 결과(조종이 얼마나 어려웠나) |
| 포기 | `x` = 실패 1회로 셈 | 정직하게 세려고 |
| 중간에 끄기 | 끝나지 않은 시도는 "interrupted"로 남기고 횟수에 안 넣음. 다음 실행 때 그 배치부터 | 노트북이 꺼져도 잃는 것 없게 |
| 성공 판정 | `PlacementTracker`(다른 모든 곳과 같음). 성공 뒤 1.5초 더 기록하고 저장 | |
| 데이터셋 | 녹화 화면이 성공으로 끝낸 시도만, 그리고 `build_dataset.py`가 판정을 다시 계산해서 성공인 것만 | 두 번 확인 |
| 저장 | 시도마다 CSV(숫자만, 손 마디 원래 값 포함) + JSON(조건·배치·설정·보정 계수·git 커밋). 진행은 `progress.json` | 영상은 저장하지 않음 |

실패가 나오면 두 조건의 성공 시범 수가 달라질 수 있다. 학습할 때 맞출지(적은 쪽에 맞춰 뽑기)는 녹화가 끝난 뒤 정하고, 녹화 중 성공률 자체도 결과로 쓴다.

## 녹화 전 수정 (2026-10-03, 첫 시도 뒤)

첫 시도 1번(90초 시간 초과)을 해 보고 "놓는 순간 너무 흔들린다"는 소감이 나왔다. 기록을 보니:
- 큐브를 4~7 cm 높이로 7.6초 들고 가다가, 내리는 중에 엄지-검지 비율이 **한 프레임만** 1.03(여는 기준 1.0 넘음)으로 튀어 집게가 순간 열렸고 큐브가 떨어졌다. 집게가 큐브를 놓친 게 아니라(그 전까지 집게-큐브 거리 1.2~1.3 cm로 일정) 손 인식이 튄 것이다.
- 그 시도에서 0.3초 안에 다시 닫힌 "깜빡 열림"이 5번, 집게 여닫기가 90초 동안 35번이었다. 손이 카메라에서 33~62 cm(중앙 46 cm)였고, 가까울 때 비율이 더 흔들렸다(프레임 간 변화 상위 10%: 40 cm 미만 0.25, 40~50 cm 0.11, 50 cm 이상 0.09. 가까이 온 때가 주로 집는 순간이라 손 모양 변화도 섞여 있다).
- 고친 것(모든 웹캠 조건 공통, `teleop_mapping.GripperSwitch`): **기준을 넘은 상태가 3프레임(약 0.1초) 이어져야 집게를 바꾼다.** 이 시도에 다시 넣으면 깜빡 열림 5 → 0, 여닫기 35 → 17. 이전 조종 기록 두 개의 여닫기(12번, 6번)는 그대로.
- 검토하고 안 한 것: 집기 잠금 범위(0.8~1.0)를 0.65까지 넓히기 → 들고 가는 동안 팔이 잠기는 프레임이 이 시도에서 25%, 이전 기록에서 3~15%라 조종이 답답해진다.
- 처리 방식이 바뀌었으므로 이 시도는 `measurements/demos_m8_pilot/`으로 옮기고(데이터셋에 안 씀) 녹화를 처음부터 다시 시작한다.
- 안내: 손을 카메라에서 **45~55 cm** 정도에 두는 게 좋다(M5 측정 범위 35~65 cm의 가운데, 가까울수록 손가락 인식이 흔들림).

## 녹화 전 수정 3 (2026-10-03, 오른손 첫 세션 뒤): 손바닥 방향 경고

오른손으로 다시 시작해 2개 성공 후 3번째에서 "흔들림이 전반적으로 너무 심해져" 중단. 기록:
- 처리 속도(31 fps, 손 인식 11~15 ms)와 손 거리(중앙 48~63 cm)는 그대로였다.
- 바뀐 건 **손바닥 방향**: 손바닥 법선의 카메라 방향 성분(1이면 정면) 중앙값이 1블록 0.71~0.77 → 이번 0.60 → 0.56 → 0.40. 손바닥이 점점 옆으로 돌아가 사진 속 손바닥 길이가 79 → 51 px로 줄었다. 그에 따라 프레임 간 깊이 튐(95%)이 1.4~2.0 → 2.8 → 12.9 → 25.2 cm, 엄지-검지 비율 흔들림 0.10 → 0.74, 손을 못 찾은 비율 0 → 19%.
- M5 측정(③ 보정을 맞춘 데이터)은 이 값이 거의 다 0.64 이상(1% 백분위)이었다 — 0.4는 측정하지 않은 자세다.
- 고친 것: 이 값이 0.6 아래면 웹캠 화면에 **"TURN PALM TO CAMERA"** 경고를 띄운다(`teleop_rig.warn_palm`). 표시만 하고 조종 처리는 그대로다.
- 녹화 안내가 바뀌었으므로 이 세션(성공 2, 중단 1)은 `measurements/demos_m8_pilot/session2_palm_sideways/`로 옮기고 다시 처음부터.

## 하는 법

1. (처음에만) 몸풀기: `uv run python scripts/teleop.py`로 5분쯤 자유롭게. 기록하지 않는다.
2. `uv run python scripts/record_demos.py`
3. 웹캠 창을 클릭하고 `스페이스`로 조종 시작. 큐브를 집어 초록 사각형에 놓고 손가락을 벌리면 성공.
4. 끝나면 화면 안내대로 `n`. 블록(10번)이 끝나면 쉬라고 나온다. 그만하려면 `q`. 다음에 같은 명령으로 이어서.
5. 진행만 보려면 `uv run python scripts/record_demos.py --status`

녹화가 끝날 때마다 Claude가 기록을 확인하고 커밋한다.

### 본 녹화

- 100개 단위(50배치 × ②·③) 모두 성공. 시도 104번: 시간 초과 1, 포기 3. 실패로 끝난 단위 0.

### 녹화 중 조건 비교 (가림을 푼 뒤 처음 봄)

| | ② 보정 없음 | ③ 깊이 보정 |
|---|---|---|
| 성공 | 50/50 | 50/50 |
| 시도 수 | 51 | 53 |
| 첫 시도 성공 | 49 | 47 |
| 성공까지 시간 중앙값 / 평균 | 25.5 / 33.9초 | 28.9 / 31.3초 |

- 같은 배치끼리 짝지어 비교하면 ③ − ② 시간 차이 중앙값 +0.3초, 평균 −2.6초, 부호 뒤집기 검정 p = 0.42 → **녹화 단계에서는 두 조건의 차이가 보이지 않는다.** 사람이 화면을 보며 바로잡기 때문에 조종 성공·시간에는 깊이 보정의 효과가 거의 드러나지 않는다. 차이가 있다면 시범의 **궤적**에 남아 있을 것이고, 그게 학습 결과(M9)에서 드러나는지가 연구 질문이다.
- 같은 배치를 두 번째로 할 때가 첫 번째보다 빠르지 않았다(중앙 +1.2초, p = 0.49). 같은 배치 반복의 학습 효과는 작다.

### 녹화하며 나온 소감과 기록 확인

- **"스페이스로 다시 시작하면 가끔 몸짓을 인식 못 하고, 집게를 몇 번 움직이면 깨어난다":** 집기 잠금(공통 처리) 때문이다. 다시 시작하는 순간 손이 반쯤 오므린 상태(엄지-검지 비율 0.86~0.98)면 "손가락을 붙이거나 펴는 중"으로 보고 팔을 고정한다. 손가락을 움직여 비율이 0.8~1.0을 벗어나면 풀린다. 465번 중 9%가 시작 직후 잠겼고, 1초 넘게 18번, 가장 길게 6.4초. 두 조건에 같은 처리라 비교에는 영향이 없다. 녹화가 끝난 뒤라 지금은 고치지 않는다. 고친다면 "다시 시작한 직후에는 잠그지 않기" 또는 잠금 표시를 더 크게.
- **"빠르게 움직이면 못 따라간다":** 지수평활(0.5), 깊이 게이트(한 프레임 10 cm 넘는 깊이 변화 무시), 시뮬 관절 모터의 속도 때문이다(1단계 측정: 8.6 cm 계단 입력에 약 0.3초). 공통 처리.
- **"창문 닦듯이"(손목은 그대로, 팔로 옮기기) 좌우·상하 모두 잘 됨**, **"웹캠 범위 때문에 클러치를 요긴하게 씀"**, **"z가 살짝 부자연스럽지만 많이 나아짐"**.

## 세션 m8b: 조건 ⑤ 손목 마커 (2026-10-04 준비)

- 목적: "사람 시범 + 깊이 오차 거의 없음" 조건. ② − ④에 섞인 "사람이 깊이 오차를 바로잡는 과정"과 "깊이와 무관한 사람 시범 특성"을 가른다(`docs/11-m9-results.md`).
- 손목 안쪽에 인쇄 마커(ArUco 4x4_50 id 0, 한 변 50 mm, `docs/marker/wrist_marker_A4.pdf`)를 붙이고, 조건 ⑤에서는 손 위치(x, y, z)를 마커에서(`marker_depth.py`, solvePnP), 집기만 MediaPipe로 읽는다. 나머지 조종 처리는 ②·③과 같다(`teleop_rig.marker_mode`).
- 계획: ⑤ 50개(학습 배치 전부) + ② 20개(며칠 사이 조종 실력 변화 확인용, ⑤에서 한 배치 중에서). ⑤ 5개 묶음 10개 사이에 ② 5개 묶음 4개를 고르게 끼움. 조작자는 내내 마커를 차고, 화면에는 조건을 표시하지 않는다.
- 녹화 전에 마커 정확도를 확인한다: `scripts/measure_marker.py --like measurements/depth_v2/20261002_232355.json` (24단계, 같은 프레임에서 마커·MediaPipe 깊이를 참값과 비교).
- 실행: `uv run python scripts/record_demos.py --session m8b` → `measurements/demos_m8b/`

- 순서: 같은 안내문 화면(영상 미저장·익명·요령) → **연습 5개**(연습용 배치 `layouts_v1.json`의 practice, 학습·평가에 안 씀, ②·③ 번갈아, 한 번씩) → 5개 중 **3개 이상 성공**하면 본 녹화, 미달이면 거기서 끝(연습 기록은 남김) → 본 녹화 ② 20개 + ③ 20개(모든 시범자에게 같은 학습 배치 20개, 5개 묶음 ABBA, 조건 가림, 90초·3번).
